# New Idea

Use this for greenfield products, rough project ideas, and immature repos that need definition before implementation planning.

## Workflow

1. Capture the idea, intended users, desired outcome, constraints, and known assumptions.
2. Write `docs/research/IDEA_BRIEF.md`.
3. Ask concise interview questions only for unknowns that research cannot answer.
4. Write `docs/research/INTERVIEW.md`.
5. Run research lanes relevant to the idea, such as users, market, technical options, risks, prior art, and constraints.
6. Write `docs/research/RESEARCH_BRIEF.md`.
7. Write `docs/PRD.md`.
8. Write or update `docs/BUILD_CONTEXT.md`.
9. Stop for review before implementation planning.

## Rules

- Do not write implementation source files inside `new-idea`.
- Keep research notes practical and source-grounded.
- Mark unresolved decisions clearly instead of guessing.
- Graduate to `deep-plan` only after the PRD and build context have been reviewed.
