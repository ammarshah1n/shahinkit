# Self-Improve

Use when asked to extract lessons, preserve a workflow improvement, or learn from a correction or failure.

## Detect

Look for user corrections, repeated guidance, verified failures and fixes, reusable workflows, and explicit preferences. Ignore generic advice, resolved trivia, and speculative improvements.

## Filter

Keep candidate only when it is new, specific, durable, actionable, and supported by a distilled fact or artifact.

## Route

| Candidate | Canonical destination |
|---|---|
| User correction or prevention rule | `CORRECTIONS.md` |
| Reusable lesson, workaround, or preference | `LEARNINGS.md` |
| Current work status or blocker | `PROJECT_STATE.md` |
| One restart instruction | `NEXT.md` |
| Skill behavior correction | Relevant `SKILL.md`, after explicit review when it changes policy |

Search destination first. Update existing entry rather than duplicate. Present proposed changes for approval when modifying instructions or durable policy. Do not auto-commit or push.

Never store or copy raw transcripts, transcript exports, or raw tool output.
