# Idea

Use this for one new product, workflow, integration, study system, or app idea.

## Flow

1. Define the proof user, desired outcome, and rejection criteria.
2. Check configured memory and local files for prior related work.
3. Decide whether this is truly new or a change to existing code.
4. If it is existing-code work, switch to `plan`.
5. If it is new, validate the idea before planning implementation.
6. Produce a short PRD and build context when the idea survives validation.
7. Stop for review before implementation planning.

## Validation

The idea can end with:

- `BUILD`: strong enough to plan.
- `NOT NOW`: useful, but blocked by missing inputs or a better sequence.
- `DO NOT BUILD`: existing tools solve it well enough or the proof user would not use it.

Validation that cannot reject the idea is not validation.
